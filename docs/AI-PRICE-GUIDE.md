# AI 模型价格维护工作文档

本文件保存在 OCU 仓库中；实际工作目录以 OCU「数据 → 模型参考价格」页面显示的路径为准，不是本文件所在目录。请仅在用户要求时执行；更新前告知用户联网检索可能暴露供应商和模型名。不要上传台账、会话内容、路径、凭据或其他私人数据。

1. 以只读方式检查工作目录 `ledger.db` 的 `usage` 表，只提取 `provider`、`model`、`created_ms` 和必要的 token 数量，定位缺价模型和消息日期；不要修改台账。读取 `prices/model-prices.json`、`prices/reverix-prices.json` 和存在时的 `report-settings.json`，保留用户已有规则。旧版文件可能位于工作目录顶层；新旧位置同时存在时停止并请用户处理冲突。
2. 首先核查实际供应商（包括中转站）的公开价格及模型对应关系；没有时才查模型官网 API 单价，标注这是参考价而非渠道账单。无法核实则保留缺价，不猜测免费、价格或模型映射。订阅价格不是 token 单价。
3. 核对币种、每百万 token 的输入、输出、推理、缓存读写、日期和价格阶梯。未知字段省略，不写零；仅在确定推理与输出同价时填写推理价。固定价格规则不能表达上下文阶梯或峰谷，记录其局限；缓存写入注明适用时长。记录 HTTPS 来源、核实时间和假设。
4. 修改前先备份 `prices/model-prices.json` 到工作目录 `backups/`，不得覆盖已有备份；保留全部其他规则。每条价格规则包含精确的 `provider`、`model`、`effective_from`（YYYY-MM-DD）、`currency`（CNY 或 USD）、已知单价字段 `input`、`output`、`reasoning`、`cache_read`、`cache_write`，以及 `source` 和 `note`。生效日期须有依据；若回溯估算，说明使用范围和不确定性。相同模型及生效日期不要重复。
5. 避免与运行中的 OCU 并发修改：先退出 OCU，使用工作目录 `.ocusage.lock` 对应的工作区锁；读取最新文件，验证 JSON 及非负有限价格后原子写入，避免覆盖并发更改。不要修改或删除其他文件。完成后告知用户修改、来源、未解决的缺价和局限；重新生成报表后参考费用才会更新，原始费用不变。

规则详情、设置优先级和操作示例见 OCU 仓库 `docs/AUTOMATION.md` 的“模型价格维护手册”。
