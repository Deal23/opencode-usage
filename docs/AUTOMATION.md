# 自动化、报表设置与验证边界

## 同步模式与状态

数据 → 同步 → 交换目录可输入路径或用 `?` 打开目录选择器。工作目录和交换目录不能相同或互相包含。默认只发送本机用量及设备来源；同页开启共享标题/项目（sync_metadata）需确认隐私，也可开启转发全部历史。手动导出每次选择完整或仅用量，默认完整，不包含正文或密钥。

CLI `ocusage export --ledger <台账> --device <设备ID> --output <文件>` 同样默认完整，含标题/路径隐私；添加 `--usage-only` 只导出用量与来源。导出不会自动采集。直接覆盖/共享数据库不是合并，应使用快照导出再导入。

每台设备发布一份用量快照和一个小型 `.status.json` 心跳文件。用量不变时快照不重写；心跳记录检查时间、最近成功采集时间及采集是否成功。接收方只将与已接收内容哈希一致的心跳关联到设备，不用心跳冒充数据已经传输成功。旧版无心跳设备仍按快照时间判断。

看板“信息完整度”显示全台账的设备来源、标题与项目覆盖率；缺少字段可能来自隐私模式或源库本身。元数据只接受较新的非空字段，无时间戳的旧快照仅补空。报表价格设置版本便于比较两端口径，不自动同步价格文件或 OpenCode 配置。

Windows 后台更新结果会在下一次启动显示。设置 → 高级 → 诊断可导出 `.state/diagnostics.json`，只含允许字段，不含原始异常、用户名路径、设备身份或对话；分享前仍需检查。

## 配置与命令

交互式 `ocu` 与 `ocusage init / sync / status / doctor` 共用设备身份、菜单配置和工作目录。无人值守模式不询问路径，也不会确认接管旧目录；请先在菜单完成旧设备绑定。

`ocusage sync --no-open --json` 分阶段采集、接收、发布和生成报告；本机源库失效时继续其他阶段，并返回非零退出码。工作目录占用返回 3，适合任务调度器跳过重叠任务。JSON 仅输出一个结果对象，不混入进度提示。诊断输出包含本机路径，分享前请脱敏。

`.state/sync-state.json` 保存每设备最近 20 个内容哈希及最新已接收快照时间。`.state/inbox/` 是内部重试队列：成功合入主台账并记录接收状态后删除副本，失败保留重试；无需用户预放文件。旧 imports 在正常启动时迁移。交换目录及其他外部源文件不删除。台账只增不删，同 ID 更新取各项用量及费用的历史较大值；身份冲突阻止写入。恢复台账后清空接收状态，但已消费的队列文件不会恢复，需要从原始导出或交换目录重新导入。

同步没有网络传输层，不管理云盘账号、不上传对话，也不声明云端或对端已经收到。首次切换“仅发布本机”不会删除任何已有台账记录。若其他设备从未直接发布过，请让其执行一次同步，或在中转机开启 `relay_history`。

## 报表设置

设置 → 报表可直接修改时区和汇率，校验通过后保存到 `report-settings.json`；价格配置文件入口保留高级规则编辑。也可以自行创建：

```json
{
  "timezone_offset": 8,
  "usd_to_cny": 7.0,
  "free_providers": [],
  "prices": [
    {
      "provider": "example",
      "model": "example-model",
      "effective_from": "2026-11-01",
      "input": 7,
      "output": 35,
      "reasoning": 35,
      "cache_read": 0.7,
      "cache_write": 7
    }
  ]
}
```

价格单位为每百万 token 人民币；按报表时区的消息日期选择最新已生效规则。使用了某类 token 却未提供该类价格时标记缺价，不默认免费。显式规则优先于内置历史规则；原记录美元费用不会被修改。未覆盖消息的零原费用不等同免费。

时区为固定 UTC 偏移，支持小数，不自动处理夏令时。本机现存会话仍按明确标注的北京时间显示；累计报表及 CLI `report` 共用报表配置。内置历史参考价格为兼容保留，不保证当前有效；建议显式配置价格。

## 定时运行

`ocusage schedule --output <文件>` 不覆盖已有文件，不注册任务。Windows 生成 XML，以登录触发、每 30 分钟重复；在任务计划程序导入，以当前用户运行，不使用 SYSTEM。macOS 生成 plist，检查后放入 `~/Library/LaunchAgents` 并用 launchctl 加载。Linux 生成 cron 行，检查后用 `crontab -e` 添加。

模板引用生成时的 Python 或独立程序绝对路径；移动安装位置后重新生成。Python 源码开发模式需要先 `pip install -e .`，不要依赖交互终端的 PYTHONPATH。同步日志最多保留当前和上一份约 2 MiB 的日志，目录不可用时返回失败。

## Windows 安装与升级

启动脚本使用 ASCII 相对路径，减少中文用户名和系统代码页造成的问题。安装后验证 CLI 版本，并广播用户环境变量变更；当前终端可能仍需重新打开。

Windows pip 自更新先构建 wheel，再启动独立安装进程等待主进程退出。日志及结果保存在提示的临时目录，失败时 wheel 保留以供重试。此方式避免入口占用，但不提供程序回滚，也不表示后台安装一定成功；需检查结果日志。独立可执行版本不执行 pip 自更新。

## 独立可执行版本

`.github/workflows/standalone.yml` 是手动运行的三平台构建工作流，生成单文件程序和 SHA256SUMS，不发布 Release、不上传 PyPI、不签名。也可本地执行：

```sh
python -m pip install . pyinstaller==6.16.0
python -m PyInstaller --onefile --name ocu --collect-all opencode_usage src/opencode_usage/standalone.py
```

无参数启动菜单，带参数进入 CLI，例如 `ocu sync --no-open --json`。固定版本发布、代码签名和分发仍需维护者单独审核；当前更新下载源仍是 main，不能视为经过签名的稳定发布渠道。

## 验证边界

### 本机端到端实测

已在独立虚拟环境安装 wheel，通过独立设备身份和工作目录验证双设备交换、来源隔离、重复同步、数据库丢失后保留历史及报告生成。真实 Windows OpenCode 源数据库以只读方式成功采集；Ubuntu WSL 也成功读取 Windows 盘上的真实源库。

使用真实 Edge 无头浏览器验证报告加载、全局筛选、空结果清理、重置及 390px 宽度无页面级横向溢出，并保存桌面/移动截图。Windows 任务模板通过 Task Scheduler COM 的 TASK_VALIDATE_ONLY 检查，未注册任务；实测发现并修复 XML 编码声明与 COM Unicode 字符串的冲突。

Windows 更新 worker 在隔离虚拟环境中验证了等待父进程退出、实际 pip 重装 wheel，以及重装后 CLI 可运行。尚未覆盖通过 GitHub 下载更新到完整入口退出的全过程。

自动测试覆盖内容哈希、来源保留、部分失败、非交互流程、价格时区以及轻量模拟 DOM 的筛选执行。Node.js 只用于可选前端测试，不是运行时依赖。

真实浏览器布局、Windows 安装器/任务计划导入/后台更新、云盘延迟、Linux/macOS 调度器，以及 Windows 与 WSL 跨系统同时运行均需真实环境验收。共享工作目录仍只支持交替运行，不应将两种系统锁接口视为已经验证的跨系统互斥保证。
