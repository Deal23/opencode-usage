# 数据、同步与恢复

## 数据在哪里？

```text
本机 OpenCode 数据库（只读） ─┐
其他设备快照 ──────────────┴→ ledger.db 主台账 → HTML / Markdown / CSV
```

每台设备独立维护台账。默认目录为 `~/.local/share/ocusage/`；Windows 为 `%USERPROFILE%\.local\share\ocusage\`。实际位置以菜单为准。

| 文件 | 用途 |
|---|---|
| `ledger.db` | 累计用量、设备来源和已保存的会话信息，最重要的数据 |
| `.state/inbox/` | 内部重试队列，成功合并后删除；失败文件保留 |
| `exports/` | 最新手动导出，文件名含本地年月日时分秒，不会先自动采集 |
| `reports/` | 最新看板、文字报告和 CSV，可重新生成，不是完整备份 |
| `backups/` | 自动台账备份，默认保留最近 5 份 |
| `menu-config.json` | 本机路径和偏好 |
| `.state/` | 程序内部状态、更新缓存、诊断和轮换日志 |

报告生成时不再创建 `reports/total.snapshot.json`；最新报告全部生成并保存状态成功后，自动清理该旧报告快照（仅普通文件且快照格式有效，无法确认则保留）。需要完整快照请选择“数据 → 导出”，直接输入文件路径，回车使用默认路径，再选择导出范围。

`reports/` 默认只生成 `report.html`、`report.md`。在“数据 → CSV”生成 `total.csv` 和 `reference-costs.csv`，固定文件名覆盖；已有 CSV 保留且不随报告更新。CLI 快照报告可用 `ocusage report ... --csv` 显式生成 CSV。

目录按需创建，空工作目录不会预先生成 `imports/`、`exports/`、`reports/`。正常使用后的结构为：

```text
工作目录/
├── ledger.db                 累计台账
├── menu-config.json          本机配置
├── workspace-owner.json      设备归属保护
├── report-settings.json      可选报表设置
├── reports/                  最新报告
├── exports/                  手动导出
├── backups/                  恢复点
└── .state/                   内部状态、重试队列与日志
```

`.ocusage.lock` 是顶层保留的进程锁，不删除或移动以兼容旧版进程。旧版顶层状态文件在新版正常启动取得锁后迁入 `.state/`，文件内容保持不变；遇到同名冲突停止迁移，不覆盖。安全整理只清理明确废弃的程序产物，不按时间或未知文件名批量删除；手工副本、其他历史报告、外部导出和保护备份保留，`exports/` 按下文仅保留最新程序导出。旧版程序不认识新路径，迁移后不要交替使用旧版。

`.state/sync-state.json` 保存接收回执，不能作为普通缓存随意删除；完整备份仍应复制整个工作目录，包括隐藏文件。

无需维护公开导入目录；手动导入直接选择文件或输入路径。旧 `imports/` 中的快照在持锁、身份校验后的启动时迁入 `.state/inbox/`，同名冲突停止、不覆盖；迁移后只删除空的旧目录，未知文件及符号链接不删除。队列仅在需要重试副本时创建。

默认导出名为 `usage-设备名-YYYYMMDD-HHMMSS.snapshot.json`，使用本地时间，设备名中的非法文件名字符替换为下划线。新导出成功并通过校验后，清理 `exports/` 内采用程序新旧命名的有效旧快照，只保留此次最新一份；导出失败保留旧文件，自定义外部路径、未知文件及符号链接不清理。

设备身份和工作目录指针在 `~/.config/ocusage/`，不要随意删除或复制给其他机器。

## 如何合并？

- 按消息 ID 去重，同 ID 的各项用量及原费用取历史较大值，不重复计数。
- 会话 ID、时间、提供商或模型发生身份冲突时，该文件停止合并；不通过清空台账解决。
- 已导入的数据继续导出，仍保留原设备 ID 和名称。旧版快照缺失的信息无法凭空恢复。
- 源库删会话或删除导入文件，不会删掉已入账的记录。首次采集前已删除的数据通常无法恢复。
- 同一条消息可关联多个采集设备，因此设备分项可能重叠，不能简单相加。
- 合并结果单独统计会话标题/项目的补齐或更新；新增消息为 0 也可能补齐会话信息。

这是累计高水位统计，不是账单核销。源数据纠正了过高用量时，不会自动降低历史值。

## 哪些信息会同步？

| 信息 | 默认隐私模式 | 可信设备模式 |
|---|---|---|
| 消息用量、原费用、时间、设备来源 | 包含 | 包含 |
| 会话标题、项目路径、元数据更新时间 | 不包含 | 包含 |
| 提示词、回复、API 密钥 | 不包含 | 不包含 |
| Agent、耗时、远端现存状态 | 暂不支持 | 暂不支持 |

上表描述自动交换。可信模式在“数据 → 同步”中主动开启，需先配置交换目录并确认隐私。手动导出默认选择“完整合并快照”，包含台账已有标题/路径及更新时间，并明确提示隐私；可显式选择“仅用量”。导出结果展示来源、标题与项目覆盖率，完整仅表示未过滤，不代表源台账没有缺失。新元数据优先于旧版本，空值不清空已有标题/项目；没有时间戳的旧数据仅补空，不覆盖已保存的非空信息。

自动交换默认只发布本机来源记录；手动导出包含全部历史。交换目录中的源文件不删除。设备心跳是独立的小文件，让“设备最近检查”和“用量数据最后变化”分开显示；它不证明对端收到数据或云盘完成传输。

报告显示标题、项目及来源覆盖率。缺失标题不等于丢失 token；隐私模式下是正常现象。“本机现存会话”只展示本机源库，不重复计入累计统计。

## 备份与恢复

刷新、合并、升级和迁移前自动备份台账，保留份数可设为 1–50。自动备份不含 OpenCode 完整对话，也不是异地备份。

1. 在设置 → 高级 → 备份与恢复查看备份、调整保留份数、立即备份或恢复，恢复需输入 `RESTORE`。
2. 恢复只回退台账，保留当前设备身份和路径；随后刷新可能重新补回源库及交换目录数据。
3. 已成功消费的内部队列文件不会因恢复重新出现，需要从原导出或交换目录重新导入。
4. 完整备份：停止写入后复制工作目录，并另存本机 `~/.config/ocusage/`；运行中的 SQLite 使用 backup API，不只复制主数据库文件。
5. 新机器应建立独立身份，再导入快照，不直接复制旧设备配置接管目录。

## 报表口径

菜单和 CLI `report` 使用同一报表引擎与报表设置；CLI `report` 只读指定快照，不写主台账。参考费用不等于账单，原始美元值不被改写。价格、汇率和时区设置见[自动化说明](AUTOMATION.md)。

不要公开上传台账、报告或快照。即使不含正文，设备名、消息 ID、时间和用量也可能敏感。
