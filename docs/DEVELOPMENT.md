# 开发手册

## 项目结构

项目使用 Python 3.9+ 和标准库，源码位于 `src/opencode_usage/`。交互入口为 `ocu`，高级命令为 `ocusage` 或 `python -m opencode_usage`。

| 模块 | 职责 |
| --- | --- |
| `core.py` | 源库读取、累计台账、快照和命令行接口 |
| `menu.py`、`interaction.py` | 菜单、配置和设备身份 |
| `sync.py`、`automation.py` | 快照合并、同步状态和自动化流程 |
| `dashboard.py`、`dashboard.html`、`markdown.py` | 数据聚合与报告 |
| `safety.py`、`locking.py`、`files.py` | 备份、进程锁和原子写入 |
| `paths.py`、`wsl_sqlite.py` | Windows / WSL 路径与数据库兼容 |
| `install.py`、`update.py` | 安装与程序更新 |

## 开发与验证

```sh
python3 -m pip install -e .
python3 -m unittest discover -s tests -v
git diff --check
```

Windows 编码兼容性可使用 `py -3 -X utf8=0` 运行测试。CI 覆盖多平台及非 UTF-8 环境；独立程序构建需手动触发。真实云盘跨设备传输、完整在线更新与正式独立发行仍需单独验收。

## 数据与兼容性约定

- 源 OpenCode 数据库只读；累计台账按消息 ID 去重，各项用量和原费用保留历史最大值，身份冲突拒绝导入。
- 手动和 CLI 导出默认包含台账已有的标题、项目路径和设备来源；自动交换默认仅发布本机来源用量，不含标题和路径。
- 导入流程共享校验和事务合并，元数据按更新时间合并，空值不清空已有信息。成功消费内部收件箱，外部文件不删除。
- 每台设备维护独立台账，通过快照交换；Windows 与 WSL 共用工作目录时仅支持交替运行。
- 刷新生成 HTML 和 Markdown；CSV 按需生成。报告、外部文件和保护备份不得随意清理。
- 保持零第三方运行时依赖；涉及真实台账、配置、设备身份或系统设置的操作应先取得明确授权。

## 开发规范

- 菜单与自动化复用同一采集、导入和报告流程；输入校验后再写入，避免重复读取与重复实现。
- 同一批次中的用量、设备来源和会话元数据须原子合并；明确反馈新增、更新、重复与失败。
- 先备份再执行可能修改台账的操作；迁移和清理只处理确认归属的文件，冲突、失败及未知文件保留。
- 安装或更新前检查入口冲突，不覆盖其他程序；保持 Windows 非 UTF-8 环境和 WSL 路径兼容。
- 界面与帮助保持一致，突出常用操作；隐私范围、同步状态和错误提示应清晰准确。
- 修改数据格式、同步或报表时补充回归测试；跨平台行为应区分自动测试结果与人工验收范围。
- 不在源码、文档、测试或示例中写入真实凭据、个人路径或设备信息。
