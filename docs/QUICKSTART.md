# 第一次使用与常见问题

## Windows + Mac，三步汇总

1. 两台机器各自安装并运行 `ocu`，分别命名为 Windows、Mac，先刷新一次。
2. 选择数据 → 同步 → 交换目录，指定各自本机看到的同一个 OneDrive 文件夹，例如 Windows 的 `%USERPROFILE%\OneDrive\OCU-sync` 和 Mac 的 `~/OneDrive/OCU-sync`（以实际路径为准）。不要选择 OCU 工作目录。
3. 等云盘传输完成，两台机器各刷新一次。查看设备来源和同步状态；需要标题/项目时，仅对可信设备开启额外共享。

不使用云盘：更新报告 → 数据与同步 → 导出快照 → 复制 JSON 文件 → 另一台数据与同步 → 导入快照。先预览整批再确认；只有旧版快照另问来源名称。输入 `?` 可选择多份文件，不可用时直接输入或拖入路径。

主菜单 `1` 刷新，`2` 数据，`3` 设置；`v` 查看已有报告（不采集或同步），`?` 帮助；回车不执行更新。目录和按需 CSV 在数据菜单内，设置完成一项后可继续设置。

看板统一在顶部选择日期、设备、提供商和模型；消息明细中的搜索只影响本表。设置 → 偏好可按编号单独修改开关，诊断默认显示检查摘要。

## 常见问题

**导出来自哪里？** 来自主台账，包含本机和已经合并的其他设备历史；导出不会先刷新，想要最新数据先选 1。

**反复转发会重复吗？** 不会按文件累加，按消息 ID 合并；设备来源保留。新版快照不再询问来源名称，旧版才补名称。

**为什么标题/项目少了？** 旧快照、仅用量导出或默认自动交换不带标题和路径。重新从源台账选择完整合并导出，再导入即可补齐已有字段，不必删除台账。手动导出现在默认完整，自动交换仍需主动开启可信模式。看板“信息完整度”显示覆盖情况；用量本身可能完整。

**需要把文件放入 imports 吗？** 不需要，直接选择或输入路径导入。内部 `.state/inbox/` 保存重试副本，失败后数据菜单显示 r 重试；旧 imports 中快照会在正常启动时迁入，空目录移除，未知文件保留。外部源文件不删除。

**为什么有设备未更新？** 检查对方是否运行刷新、云盘是否完成传输，以及源库采集是否成功。无心跳的旧版设备只能根据快照时间判断；不等于数据一定丢失。

**Windows 提示找不到 ocu？** 完全退出并重开终端或 VS Code。仍不可用时用 PowerShell 执行：

```powershell
& "$HOME\.local\bin\ocu.cmd"
```

**更新失败怎么办？** 下一次启动会显示后台安装结果和日志位置；可重新下载源码运行 `py -3 install.py`，不需删除台账。

**如何分享诊断？** 设置 → 高级 → 诊断 → 导出脱敏诊断，只输出允许的状态字段，不包含用户名路径、设备身份或对话。分享前仍请自行检查。
